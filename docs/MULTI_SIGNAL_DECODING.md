# 🎵 Декодирование нескольких параллельных сигналов

**Русский** | [English](MULTI_SIGNAL_DECODING.en.md)

## Описание

Модуль `multi_signal_decoder.py` позволяет декодировать несколько параллельных морзе-сигналов на одной аудиозаписи, различая их по:

- **Частоте (тональности)** - разные сигналы на разных частотах
- **Скорости передачи (WPM)** - сигналы с разной скоростью
- **Амплитуде (громкости)** - сигналы разной силы

## Использование

### Автоматическое определение частот

```bash
python morse_cli.py multi recording.wav --auto-detect
```

Система автоматически найдёт частотные пики в спектре и создаст для каждого отдельный декодер.

### Ручное указание частотных диапазонов

```bash
python morse_cli.py multi recording.wav --bands "400-800,900-1300,1500-1900"
```

Укажите до 3-х частотных диапазонов через запятую в формате `min-max`.

### С поиском информации о позывных

```bash
python morse_cli.py multi recording.wav --auto-detect --lookup-callsigns
```

## Как это работает

1. **Анализ спектра**: FFT-преобразование аудио для поиска частотных пиков
2. **Создание фильтров**: Для каждого диапазона создаётся узкополосный bandpass-фильтр
3. **Параллельное декодирование**: Каждый частотный диапазон обрабатывается независимо
4. **Сортировка по качеству**: Результаты сортируются по проценту правильно распознанных символов

## Параметры автоопределения

- **min_freq**: Минимальная частота поиска (по умолчанию 300 Hz)
- **max_freq**: Максимальная частота поиска (по умолчанию 3000 Hz)
- **num_peaks**: Максимальное количество сигналов (по умолчанию 3)
- **peak_threshold**: Минимальная амплитуда пика относительно максимума (0.1 = 10%)
- **bandwidth**: Ширина полосы фильтра вокруг пика (по умолчанию ±200 Hz)

## Ограничения

- Сигналы должны иметь **достаточное частотное разделение** (минимум 100-200 Hz)
- Для слабых сигналов требуется хорошее соотношение сигнал/шум
- Одновременная передача на очень близких частотах может привести к интерференции
- Максимум 3-5 сигналов одновременно (в зависимости от качества записи)

## Сценарии использования

### 1. WebSDR записи с несколькими станциями

```bash
python morse_cli.py multi websdr_7mhz.wav --auto-detect --lookup-callsigns
```

### 2. Конкурсные записи (несколько станций в эфире)

```bash
python morse_cli.py multi contest_recording.wav --bands "500-700,800-1000,1100-1300"
```

### 3. Поиск слабых сигналов на разных частотах

```bash
python morse_cli.py multi dx_recording.wav --auto-detect
```

## Программный интерфейс

```python
from modules.multi_signal_decoder import MultiSignalDecoder

# Создание декодера
decoder = MultiSignalDecoder(
    sample_rate=8000,
    auto_detect=True  # или frequency_bands=[(400,800), (900,1300)]
)

# Декодирование
results = decoder.decode_multi_signal(
    'recording.wav',
    pulse_percentile=85,
    verbose=True
)

# Обработка результатов
for signal in results:
    print(f"Частота: {signal['center_frequency']:.0f} Hz")
    print(f"Текст: {signal['text']}")
    print(f"Качество: {signal['quality']:.1f}%")
```

## Советы по улучшению результатов

1. **Узкие полосы**: Используйте узкие частотные диапазоны (400 Hz) для лучшего разделения
2. **Предварительная фильтрация**: Удалите шум из записи перед обработкой
3. **Подбор параметров**: Экспериментируйте с `pulse_percentile` для каждого сигнала
4. **Ручные диапазоны**: Если автоопределение не работает, задайте частоты вручную

## Отличия от обычного режима

| Параметр | Обычный режим | Multi режим |
|----------|---------------|-------------|
| Количество сигналов | 1 | До 3-5 |
| Частотный фильтр | Один широкий | Несколько узких |
| Скорость обработки | Быстрая | Медленнее (×N сигналов) |
| Качество на один сигнал | Выше | Может быть ниже |
| Сложность использования | Простая | Требует настройки |

---

**⚠️ Примечание о статусе функциональности:**

Режим multi-signal декодирования является **экспериментальным**. При тестировании на реальных WebSDR записях наблюдались следующие проблемы:

- Ложное определение гармоник как отдельных сигналов
- Снижение качества декодирования при разделении на узкие полосы
- Сложность автоматической настройки параметров

**Рекомендация:** Для большинства задач используйте стандартные команды `auto` и `batch`, которые показывают более стабильные результаты на одиночных сигналах. Multi-signal режим подходит для специфических сценариев с действительно параллельными передачами на разных частотах.

---

**Примечание**: Эта функциональность является **дополнением** к основному декодеру и не заменяет стандартные команды `auto` и `batch` для работы с одиночными сигналами.

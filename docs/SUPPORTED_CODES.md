## 📋 Что означает поддержка

Ниже приведён фактический состав словарей [code_dictionaries.py](../modules/code_dictionaries.py), а не подтверждение соответствия международным или ведомственным стандартам. Значения кодов взяты из проекта; их применимость зависит от контекста. Совпадение короткого слова со словарём не доказывает, что передавалась команда.

Аудиодекодер преобразует CW в текст; `ProceduralCodeDetector` отдельно ищет коды в готовом тексте. По умолчанию используется точное сопоставление слов после перевода в верхний регистр и разделения по пробелам. Внешние знаки препинания снимаются; `?` у Q/Щ/QN-кода сохраняется в поле `is_question`. Внутри слова символы не удаляются. Многословные `НЕ ПНЛ` и `PAN PAN` распознаются по границам слов. Нечёткий поиск **выключен** по умолчанию; его можно включить через API, но он повышает риск ложных совпадений.

## 🇷🇺 Как получить российские сокращения

`--ru` меняет язык консоли, а не алфавит записи. `decode` выводит единый отчёт по EN/RU, включая расширенные категории. Одинаковая структура и совпадающие записи не удваиваются; разные структуры помечены EN/RU. Повтор того же российского кода в legacy-категории скрыт только в этом отчёте, данные API сохранены. `auto`/`batch` сохраняют оба анализа в TXT; рабочая оценка автоподбора по-прежнему использует EN и не получает дополнительных бонусов за расширение русского словаря. `multi` анализирует свой текст по всем категориям. `auto --analyze` не существует; `decode --analyze` сохранён для совместимости и не добавляет повторную сводку.

Надёжный способ получить словарные пояснения из русского текста:

```python
from modules.procedural_codes import ProceduralCodeDetector

detector = ProceduralCodeDetector()
result = detector.detect_codes("РПТ АЛ")
for item in result["ru_procedural_abbr"]:
    print(item["code"], "—", item["meaning"])
```

Результат:

```text
РПТ — Повторите / я повторяю
АЛ — Всё, что только было передано
```

Чтобы получить текст из записи, сначала подберите параметры. Этот вызов также сохраняет TXT и конфиг рядом с аудио:

```python
from modules.auto_tune import auto_tune_parameters
from modules.procedural_codes import ProceduralCodeDetector

decoded = auto_tune_parameters("tests/fixtures/noisy_cw.mp3", mode="fast")
if decoded is None:
    raise RuntimeError("Decoding failed")
detector = ProceduralCodeDetector()
result = detector.detect_codes(decoded["text_ru"])
print(result["ru_procedural_abbr"])
```

Поля результата включают `q_codes`, `y_codes`, `z_codes`, `shch_codes`, `ru_procedural_abbr`, `soviet_codes`, `cw_abbreviations`, `prosigns`, `sinpo_codes`, `maritime_codes`, `meteo_codes`, `service_signals`, `urgency_level`, `callsigns`, `message_structure`, `check_field`, `message_number`. Служебные сигналы используют ключ `signal`, обычные коды — `code`. `CHECK N` и `NR N` извлекаются отдельно. Результаты словарей содержат русские `meaning`; форматированный отчёт можно запросить через `detector.format_analysis(result, language="en")`, но для полного доступа к категориям используйте словарь результата.

Для нечёткого поиска создайте `ProceduralCodeDetector(use_fuzzy_matching=True, max_errors=1)`. Его результаты и структура некоторых элементов отличаются от точного режима; это предположения о похожих кодах, а не восстановление достоверного текста.

## 📊 Состав словарей

Количество — число ключей в конкретном словаре. Не суммируйте его как количество уникальных автоматически распознаваемых команд: категории пересекаются, а фонетические алфавиты — вспомогательные данные. RST теперь извлекается в `rst_reports` только после явного маркера `RST`. Коды и русские фонетические слова сохранены без перевода в обеих версиях.

## 🔤 Алфавиты Морзе и неоднозначные знаки

Точные таблицы EN/RU и `PROSIGNS_MORSE` находятся в [morse_decoder.py](../modules/morse_decoder.py). Доступны латинские и русские буквы, цифры и знаки препинания. Prosigns проверяются раньше обычных букв; поэтому одинаковый рисунок может отображаться как `<AR>`, `<BT>`, `<KN>`, `<AS>` вместо пунктуации. Рисунок `..-.` декодируется как F/Ф, `..-..` — как Э в RU; старое перекрытие знаком `<INT>` исправлено. `..--..` остаётся `?`, `-.-` — K/К. Слитные `...---...` и `-.-..-..` декодируются как `<SOS>` и `<CL>`. Неизвестный рисунок обозначается `□`.

Детектор текста распознаёт помеченные слитные знаки вида `<AR>`; обычное слово `AR` может быть CW-сокращением. Не все 15 словарных названий prosigns имеют отдельный выход аудиодекодера: некоторые являются синонимами.

## 🧠 Профили, контекст и метаданные

```python
from modules.procedural_codes import ProceduralCodeDetector

result = ProceduralCodeDetector(profile="ru_soviet").detect_codes(
    "РПТ АА 24 К ЩРЖ? ЗАН ШТОРМ RST 599"
)
print(result["shch_codes"][0]["is_question"])  # True
print(result["ru_z_codes"])
print(result["soviet_urgency_levels"])
print(result["rst_reports"])
```

| Профиль API | Категории |
| --- | --- |
| `all` (по умолчанию) | Все словари, возможны несколько трактовок одного кода |
| `ham_cw` | Общие Q-коды и CW-сокращения |
| `arrl_traffic` | Сетевые QN-сигналы и CW-сокращения |
| `ru_soviet` | Щ-, З-коды, российские сокращения, советские legacy-коды и срочность |
| `maritime` | Общие Q-коды и морские коды |

Во всех профилях остаются prosigns, служебные сигналы и RST; позывные и общая эвристика структуры анализируются независимо. CLI использует `all`; отдельного аргумента профиля пока нет. В `all` короткие `К`, `Р`, `Ц`, `У`, `В`, `З`, `Щ`, `Ь` тоже дают словарные совпадения — для целевого анализа выбирайте профиль. Совпадения двухбуквенных слов следует оценивать по соседним маркерам, а не принимать за доказательство команды.

Элементы категорий содержат `code_system`, `source`, `exact_match`; помеченные prosigns — `is_prosign`, Q/Щ/QN — `is_question`. `source` обозначает происхождение перенесённой таблицы, а не отдельную проверку каждой строки. Численная `confidence` есть у старого нечёткого поиска; точному словарному совпадению искусственная вероятность не назначается. Новые QN/З-коды, российские сокращения и приоритеты распознаются точно и при `use_fuzzy_matching=True`.

`SOVIET_CODES_LEGACY` — совместимый алиас `SOVIET_CODES`, а `soviet_codes` — прежний ключ результата. Слова `ПРМ`, `ПРД`, `КНЦ` и другие legacy-записи не объявляются единой официальной таблицей. Y-коды зависят от службы и периода. Морской словарь — ограниченная выборка, а не полный международный свод. `SECURITE`/`SÉCURITÉ` добавлены как сигналы безопасности; старое `SECURITY` сохранено для совместимости. `PAN PAN` распознаётся целиком, прежний `PAN` также остаётся.

## 📡 Примеры радиообмена

- `ЦЩ ЦЩ ЦЩ ДЕ <ПОЗЫВНОЙ>` — общий вызов всем станциям.
- `<ПОЗЫВНОЙ> ДЕ <ПОЗЫВНОЙ> ЩРЖ? К` — готовность и приглашение ответить.
- `АС 10 К` — ожидание (в примере — 10 минут) и приглашение передавать.
- `РПТ ГР 12 15 К` — повторите группы 12 и 15.
- `РПТ АА 24 К` — повторите всё после группы 24.
- `РПТ АБ 5 К` — повторите всё до группы 5.
- `РПТ БН 3 12 К` — повторите всё между группами 3 и 12.
- `АР` — конец сообщения; `СК` — конец работы связи; `ЖЖЖ` — настройка.

Это примеры толкования человеком. Детектор выделяет словарные группы; он не строит семантическую команду «повторить группы» и не выводит единицы времени из одного числа. Уголки вокруг `<ПОЗЫВНОЙ>` обозначают место для реального позывного. Обычные `АР`/`СК` в тексте не доказывают слитность знака в аудио.

## 📈 Расшифровка RST

`RST` — Readability / Strength / Tone: читаемость, сила, тон. Детектор принимает `RST 599`: R=1–5, S=1–9, T=1–9. Число `599` без маркера не трактуется как RST; `RST 699` отклоняется. Отсутствующий тон или автоматическое распознавание голосового RS здесь не реализованы.

| R | Читаемость |
| --- | --- |
| 1 | Неразборчиво |
| 2 | Едва разборчиво, отдельные слова |
| 3 | Разборчиво с большим трудом |
| 4 | Разборчиво почти без труда |
| 5 | Отлично разборчиво |

| S | Сила сигнала |
| --- | --- |
| 1 | Едва заметный сигнал |
| 2 | Очень слабый |
| 3 | Слабый |
| 4 | Умеренный |
| 5 | Довольно хороший |
| 6 | Хороший |
| 7 | Умеренно сильный |
| 8 | Сильный |
| 9 | Очень сильный |

T — качество тона, 1–9. Эти переданные оценки не равны измерениям `signal_analyzer.py`. Советские `ВЬ` (погода), `ПВЬ` (прогноз), `ТАФ` и `ТАФОР` входят в российские сокращения; `QFE`/`QNH` — в общий Q-словарь.

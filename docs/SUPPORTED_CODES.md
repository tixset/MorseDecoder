## 📋 Что означает поддержка

Ниже приведён фактический состав словарей [code_dictionaries.py](../modules/code_dictionaries.py), а не подтверждение соответствия международным или ведомственным стандартам. Значения кодов взяты из проекта; их применимость зависит от контекста. Совпадение короткого слова со словарём не доказывает, что передавалась команда.

Аудиодекодер преобразует CW в текст; `ProceduralCodeDetector` отдельно ищет коды в готовом тексте. По умолчанию используется точное сопоставление слов после перевода в верхний регистр и разделения по пробелам. Знаки препинания у слова могут мешать совпадению. Нечёткий поиск **выключен** по умолчанию; его можно включить через API, но он повышает риск ложных совпадений.

## 🇷🇺 Как получить российские сокращения

У CLI нет флага принудительного выбора полного русского анализа. `--ru` переводит консоль, `auto` анализирует коды в EN, а `decode --analyze` показывает только краткие счётчики и не гарантирует выбор русского текста. `auto --analyze` не существует.

Надёжный способ получить словарные пояснения из русского текста:

```python
from modules.procedural_codes import ProceduralCodeDetector

detector = ProceduralCodeDetector()
result = detector.detect_codes("РПТ АЛ")
for item in result["ru_procedural_abbr"]:
    print(item["code"], "—", item["meaning"])
```

Результат:

```text
РПТ — Повторите
АЛ — Всё, что только передано
```

Чтобы получить текст из записи, сначала подберите параметры. Этот вызов также сохраняет TXT и конфиг рядом с аудио:

```python
from modules.auto_tune import auto_tune_parameters
from modules.procedural_codes import ProceduralCodeDetector

decoded = auto_tune_parameters("tests/fixtures/noisy_cw.mp3", mode="fast")
if decoded is None:
    raise RuntimeError("Decoding failed")
detector = ProceduralCodeDetector()
result = detector.detect_codes(decoded["text_ru"])
print(result["ru_procedural_abbr"])
```

Поля результата включают `q_codes`, `y_codes`, `z_codes`, `shch_codes`, `ru_procedural_abbr`, `soviet_codes`, `cw_abbreviations`, `prosigns`, `sinpo_codes`, `maritime_codes`, `meteo_codes`, `service_signals`, `urgency_level`, `callsigns`, `message_structure`, `check_field`, `message_number`. Служебные сигналы используют ключ `signal`, обычные коды — `code`. `CHECK N` и `NR N` извлекаются отдельно. Результаты словарей содержат русские `meaning`; форматированный отчёт можно запросить через `detector.format_analysis(result, language="en")`, но для полного доступа к категориям используйте словарь результата.

Для нечёткого поиска создайте `ProceduralCodeDetector(use_fuzzy_matching=True, max_errors=1)`. Его результаты и структура некоторых элементов отличаются от точного режима; это предположения о похожих кодах, а не восстановление достоверного текста.

## 🔤 Алфавиты Морзе и неоднозначные знаки

Точные таблицы EN/RU и `PROSIGNS_MORSE` находятся в [morse_decoder.py](../modules/morse_decoder.py). Доступны латинские и русские буквы, цифры и знаки препинания. Prosigns проверяются раньше обычных букв; поэтому одинаковый рисунок может отображаться как `<AR>`, `<BT>`, `<KN>`, `<AS>` вместо пунктуации. Текущее соответствие `..-.` → `<INT>` также перекрывает F/Ф. Это ограничение реализации, а не определение универсального алфавита. Неизвестный рисунок обозначается `□`.

Детектор текста распознаёт помеченные слитные знаки вида `<AR>`; обычное слово `AR` может быть CW-сокращением. Не все 11 словарных названий prosigns имеют отдельный выход аудиодекодера: некоторые являются синонимами.
